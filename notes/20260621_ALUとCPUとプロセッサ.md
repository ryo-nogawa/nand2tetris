# ALUとCPUとプロセッサ

> 作成日: 2026-06-21
> 分類: Project 2 ブール演算 / Project 5 コンピュータアーキテクチャ

## 概要

ALU（算術論理演算ユニット）は「計算だけを担当する部品」で、CPU の中の一部品にすぎない。CPU は ALU・レジスタ・制御ユニットをまとめた「計算する装置一式」。プロセッサは処理装置の総称で、普段は CPU とほぼ同義。大小関係は **ALU ＜ CPU ≦ プロセッサ**。

## 解説

### ALU とは（Arithmetic Logic Unit / 算術論理演算ユニット）

- **ひとことで言うと**: コンピュータの「計算する場所」。足し算・引き算・AND・OR などあらゆる計算を1か所で引き受ける部品で、CPU の心臓部。
- アプリ開発で例えるなら `a + b` や `a & b` を実際に計算している裏方の実行エンジン。
- 自分では「次に何を計算すべきか」を決められず、命令されたとおり計算するだけの「電卓」のような存在。

#### Hack ALU の入出力

```
        x[16] ──→┌─────────┐
                 │         │
        y[16] ──→│   ALU   │──→ out[16]  （計算結果）
                 │         │──→ zr        （結果が0か？）
  6本の制御 ────→│         │──→ ng        （結果が負か？）
 (zx,nx,zy,ny,f,no)        │
                 └─────────┘
```

| 端子 | 役割 |
|------|------|
| `x[16]`, `y[16]` | 計算する2つの入力（16ビット） |
| `out[16]` | 計算結果 |
| 6本の制御ビット | 「どんな計算をするか」を指定する |
| `zr` | 結果が 0 なら 1（zero） |
| `ng` | 結果が負なら 1（negative） |

#### キモ：6本のスイッチで18種類の計算を切り替える

ALU は計算ごとに別々の回路を持つのではなく、6本の制御ビットの組み合わせで動作を切り替える。

| ビット | 意味（1のとき） |
|--------|----------------|
| `zx` | x を 0 にする（zero x） |
| `nx` | x を反転する（not x） |
| `zy` | y を 0 にする |
| `ny` | y を反転する |
| `f` | 1なら加算(x+y) / 0なら AND(x&y) |
| `no` | 出力を反転する（not out） |

この6本のオン/オフだけで `x+y`・`x-y`・`x&y`・`x|y`・`x+1`・`0`・`-1` など18種類の計算を1つの回路で実現できる。

- **例: 「x - y」**: 引き算専用の回路は無いが、`x - y = 足し算回路(f=1) + ビット反転` で実現する。これは「引き算＝負の数の足し算」という [[20260613_2の補数]] と直結。反転(`nx`/`ny`/`no`)と加算(`f`)を組み合わせれば引き算が作れる。

#### なぜこの設計が賢いのか

- **回路の節約**: 計算の種類ごとに専用回路を作らず、1つの回路を使い回せる。
- **制御が単純**: CPU は「6ビットを送るだけ」で計算内容を指示できる。この6ビットは後で学ぶ機械語の命令の一部になる。

### ALU・CPU・プロセッサは同じものか？ → 違う（入れ子の関係）

```
┌─────────────────────────────────────┐
│ プロセッサ ≒ CPU                       │
│  ┌──────────┐  ┌──────────┐         │
│  │   ALU    │  │ レジスタ  │          │
│  │（計算係） │  │（記憶係）  │         │
│  └──────────┘  └──────────┘         │
│  ┌────────────────────────┐         │
│  │ 制御ユニット（指揮係）     │         │
│  └────────────────────────┘         │
└─────────────────────────────────────┘
```

- **ALU は CPU の中の一部品**。
- **プロセッサと CPU はほぼ同じ意味**で使われる。

#### CPU（Central Processing Unit / 中央処理装置）

ALU を含む、いくつかの部品を組み合わせた「計算する装置一式」。最低限この3つの係を持つ。

| 係 | 担当部品 | 役割 |
|----|---------|------|
| 計算係 | **ALU** | 実際に計算する |
| 記憶係 | **レジスタ**（[[20260613_tickとtock]] で学んだ記憶素子の集まり） | 計算途中の値を一時保管 |
| 指揮係 | **制御ユニット** | 命令を読み解き、ALU やレジスタに指示を出す |

ALU が「電卓」なら、CPU は「電卓＋メモ帳＋それを操作する人」がワンセットになったもの。nand2tetris では Project 5 で ALU ＋ Register/PC ＋命令デコードを組み合わせてこの CPU を作る。

#### プロセッサ

「処理をするもの」全般を指すやや広い言葉。

- 日常会話やPCのスペック表で「プロセッサ」と言えば、ほぼ CPU と同義（例: 「Intel のプロセッサ」＝ CPU）。
- 厳密には GPU（画像処理プロセッサ）や DSP（信号処理プロセッサ）なども「プロセッサ」の一種。
- 「プロセッサ」は分類名・総称、「CPU」はその中でコンピュータの中心的な処理を担うものを特に指す呼び方。

## ポイント・補足

- 用語の大小関係: **ALU ＜ CPU ≦ プロセッサ**

| 用語 | 正体 | 関係 |
|------|------|------|
| ALU | 計算専用の部品 | CPU の中にある一部品 |
| CPU | ALU 等をまとめた装置 | プロセッサの代表格 |
| プロセッサ | 処理装置の総称 | 普段は CPU とほぼ同義 |

- 全体の中での位置づけ:

```
記憶（Project 3で作った RAM/Register）── 値を保管
        ↓ 値を渡す
   ALU（Project 2）────────────────── 計算する
        ↓ 結果を戻す
   CPU（Project 5でこれらを統合）────── 命令に従って指揮する
```

- Project 3 で「記憶」を作り終えたので、「計算する ALU」＋「記憶する RAM/Register」が揃った。Project 5 ではこの2つを PC（プログラムカウンタ）でつなぎ、命令を次々実行する CPU に組み上げる。
